# R8.1A — Mainnet Dry Run Preparation

**Status:** Preparation and validation only.  
**Does not enable:** Mainnet gameplay, Mainnet GameEscrow production usage, or payment migration.

This stage answers: **Is WheelWin ready to perform a controlled Mainnet deployment?** with a deterministic **PASS** / **FAIL**.

## Defaults (unchanged)

| Network | Escrow default | Notes |
|---------|----------------|-------|
| Testnet | `game` | GameEscrow remains the testnet path |
| Mainnet | `v4` | GameEscrow **not** production-enabled |

- Feature flag `GAME_ESCROW_MODE` retained
- Deployer wallet remains `WalletContractV4R2`
- No player payment / settlement / TonConnect / Page4–6 changes

## Validation steps

1. Load separated profiles from `server/config/tonNetworkProfiles.js` (`testnet`, `mainnet`).
2. Validate Mainnet configuration (required env, network, wallet config, artifact, escrow mode).
3. Probe deployer wallet identity (`WalletContractV4R2`, workchain, wallet id, derived address).
4. Compare derived address to `TON_MAINNET_DEPLOYER_EXPECTED_ADDRESS` (mismatch = FAIL).
5. Verify `GameEscrow.code.boc` exists, SHA256 matches, and is loadable by the StateInit builder.
6. Confirm rollback safety: Mainnet escrow mode is still `v4`.
7. Review diagnostics / readiness script output.

## Required environment variables

Fill these for a Mainnet dry-run **PASS** (no secrets committed to git):

| Variable | Purpose |
|----------|---------|
| `TON_MAINNET_ENDPOINT` | Mainnet TonCenter JSON-RPC URL (defaults to public TonCenter if unset) |
| `TON_MAINNET_ORACLE_ADDRESS` | Mainnet oracle wallet |
| `TON_MAINNET_DEPLOYER_EXPECTED_ADDRESS` | Expected deployer (pin for identity match) |
| `TON_MAINNET_GAME_ESCROW_MODE` | Must be `v4` for R8.1A (default `v4` when unset) |
| `TON_GAME_ESCROW_ARTIFACT_SHA256` | SHA256 of `server/payment/ton/artifacts/GameEscrow.code.boc` |

Optional:

| Variable | Purpose |
|----------|---------|
| `TON_DEPLOYER_MNEMONIC` | Enables live wallet identity + balance probe |
| `TON_API_KEY` | TonCenter API key for balance/seqno |
| `TON_MAINNET_DRY_RUN_DEBUG` | `true` / `1` prints `TON_MAINNET_DRY_RUN_DEBUG` block |
| `TON_NETWORK` | Keep `testnet` during dry-run prep (do **not** switch production yet) |

## How to run

From repo root:

```bash
node server/scripts/check-mainnet-readiness.js
```

With dry-run diagnostics:

```bash
# PowerShell
$env:TON_MAINNET_DRY_RUN_DEBUG="true"
node server/scripts/check-mainnet-readiness.js
```

Exit code: `0` = **PASS**, `1` = **FAIL**.

## Failure scenarios

| Scenario | Result |
|----------|--------|
| Missing `TON_MAINNET_ORACLE_ADDRESS` / expected deployer / artifact SHA | **FAIL** (configuration) |
| Invalid escrow mode (not `v4` / `game`) | **FAIL** (hard error, no silent fallback) |
| `TON_MAINNET_GAME_ESCROW_MODE=game` | **FAIL** (rollback safety — GameEscrow not enabled in R8.1A) |
| Derived wallet ≠ expected address | **FAIL** (wallet identity) |
| Wrong wallet type / workchain / missing wallet id (live probe) | **FAIL** |
| Artifact missing or SHA mismatch | **FAIL** |
| Artifact present but not loadable as code cell | **FAIL** |
| Mnemonic absent | wallet identity **SKIP** (overall may still **FAIL** if config incomplete) |

On `TON_NETWORK=mainnet`, startup uses the same gates and **fails process start** on invalid Mainnet configuration (no silent fallback). Testnet active runtime is unchanged: readiness may report FAIL until Mainnet env is filled, without blocking testnet.

## Rollback behavior

R8.1A keeps Mainnet on **v4**:

```text
Mainnet dry-run / issue
    ↓
TON_MAINNET_GAME_ESCROW_MODE=v4   (default)
GAME_ESCROW_MODE=v4               (active rollback switch when needed)
    ↓
restart backend
    ↓
new games use WalletContractV4 path
```

- No Mainnet GameEscrow production cutover in this stage
- Testnet continues with GameEscrow (`game`) by default
- Emergency rollback docs: [Mainnet-Architecture.md](../architecture/Mainnet-Architecture.md#emergency-rollback)
