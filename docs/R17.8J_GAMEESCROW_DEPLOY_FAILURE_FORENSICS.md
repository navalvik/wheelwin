## 1. GameEscrow deploy lifecycle diagram

```text
PAYMENT_CONNECTION_READY (wallet barrier cleared)
  │
  ▼
PaymentSessionManager.createAndRequest
  status: WAITING_FOR_PAYMENTS, paymentDeadline scheduled
  emit PAYMENT_SESSION_UPDATED (no contractAddress yet)
  │
  ▼
GameContractManager._handlePaymentSessionUpdated
  all participants PAYMENT_REQUESTED (or beyond)
  → createContractRequest
       buildGameContractSnapshot (server wallets + oracle + owner)
       status: NOT_CREATED → CREATING → CREATED → AWAITING_PAYMENTS
       → READY_FOR_BLOCKCHAIN
  │
  ▼
GameContractManager._beginDeploy (async, void)
  status: DEPLOYING
  emit CONTRACT_DEPLOYING → archive "BEGIN_DEPLOY"
  │
  ▼
TonGameContractAdapter.deployContract (live) OR GameContractDeployAdapter (stub)
  │
  ├─ buildGameEscrowWallet (StateInit from artifact + snapshot)
  ├─ beginTonDeployDebug (forensics)
  │
  ├─ [live + mnemonic] _broadcastDeploy
  │     _sendOracleMessage(DEPLOY)
  │       WALLET_CREATED → SEQNO_READ → BOC_SEND → broadcastTransaction
  │       _waitForDeployerSeqnoAdvance (seqno must advance)
  │     _waitUntilEscrowActive (account exists on chain)
  │
  └─ [no mnemonic] placeholder broadcast (dev/CI only)
  │
  ├─ FAIL → return { ok: false, reason }
  │
  └─ SUCCESS → { ok: true, contractAddress, deploymentTxId }
  │
  ▼
[gameEscrowMode === "game" on live adapter only]
  initGame (oracle message INIT_GAME)
  openPayments (oracle message OPEN_PAYMENTS, 3 player wallets)
  │
  ├─ FAIL → GAME_CONTRACT_DEPLOY_FAILED (post-deploy)
  │
  └─ SUCCESS
  │
  ▼
status: DEPLOYED → AWAITING_PLAYER_PAYMENTS
  emit GAME_CONTRACT_DEPLOYED
  emit GAME_CONTRACT_READY_FOR_PAYMENTS
  → PaymentSessionManager.issueDeployedPaymentRequests
  → PAYMENT_REQUEST / AWAITING_PLAYER_CONFIRMATION
```

## 3. All `GAME_CONTRACT_DEPLOY_FAILED` emitters

**Only two emit sites — both in `GameContractManager._beginDeploy` (`server/gameplay/GameContractManager.js`).**  
No other file emits this event.

### Path A — Adapter deploy failed (before/on-chain deploy)

| Field | Value |
|-------|--------|
| **File** | `GameContractManager.js` |
| **Function** | `_beginDeploy` |
| **Trigger** | `!result?.ok \|\| !result.contractAddress` after `await deployAdapter.deploy()` |
| **Error passed** | `result.reason ?? "deploy_failed"` → `current.deployError` |
| **Recovery** | `failSession(roomId, reason)` via EventBus subscriber; room destroyed |

**Upstream reasons from `TonGameContractAdapter.deployContract`:**

| Reason string | Trigger condition |
|---------------|-------------------|
| `invalid_deploy_request` | Missing contractId/snapshot |
| `deploy_failed` | Catch-all exception in deployContract |
| `broadcast.reason` (varies) | `_broadcastDeploy` / `_sendOracleMessage` threw (e.g. TonCenter HTTP error) |
| `escrow_activation_failed` | Activation helper default |
| `escrow_activation_timeout` | Account not active within `escrowActivationTimeoutMs` (default 60s) |
| `escrow_activation_missing_address` | Empty contract address |
| `deploy_timeout` | `GameContractManager` Promise.race exceeded `gameContractDeployTimeoutMs` (default **2 min**) |
| `deploy_exception` | Uncaught exception in `_beginDeploy` try/catch |

**From `_sendOracleMessage` / seqno confirmation (propagates as exception → often `deploy_failed` in outer catch):**

| Reason pattern | Category |
|----------------|----------|
| `deployer_seqno_confirmation_timeout \| operation=...` | Network / chain confirmation timeout (default 30s poll) |
| TonCenter HTTP errors (e.g. `TonCenter HTTP 500`) | Provider/RPC failure |
| TX lookup failures when `resolveAccountTxHash: true` | Confirmation / indexing |

**Stub adapter (`GameContractDeployAdapter`) reasons:**

| Reason | Trigger |
|--------|---------|
| `invalid_deploy_request` | Missing args |
| `deploy_stub_failed` | `shouldFail=true` (tests) |
| `invalid_stub_address` | Address build error |

### Path B — Post-deploy GameEscrow activation failed

| Field | Value |
|-------|--------|
| **File** | `GameContractManager.js` |
| **Function** | `_beginDeploy` (try/catch after deploy success) |
| **Trigger** | `initGame` or `openPayments` throws or returns `!ok` |
| **Error passed** | `error.message` e.g. `oracle_address_missing`, `init_game_failed`, `open_payments_failed`, `game_escrow_payments_open_failed` |
| **Recovery** | Same — second `GAME_CONTRACT_DEPLOY_FAILED` emit → failSession |

**`initGame` / `openPayments` explicit failure reasons (`TonGameContractAdapter.js`):**

| Reason | Condition |
|--------|-----------|
| `invalid_init_game_request` | Missing contractAddress/oracle/owner/contractIdHash/snapshotHash |
| `init_game_requires_game_escrow_mode` | Mode not `game` |
| `init_game_failed` | Catch on INIT_GAME send |
| `invalid_open_payments_request` | Missing contract or `< 3` players |
| `open_payments_requires_game_escrow_mode` | Mode not `game` |
| `open_payments_failed` | Catch on OPEN_PAYMENTS send |

### Silent non-emit paths (no `GAME_CONTRACT_DEPLOY_FAILED`)

`_beginDeploy` returns early **without** emitting if:

- Contract missing from registry after await
- Status no longer `DEPLOYING` (e.g. room destroyed mid-deploy)

These do **not** match the observed `payment.status: PAYMENT_FAILED` + archive payment-failed flag (those require explicit failSession).

## 6. TON deploy failure categories (code-supported)

| Category | Supported by code? | Typical reason strings / evidence |
|----------|-------------------|-----------------------------------|
| Missing configuration | **Yes** | `oracle_address_missing`, missing owner in snapshot, missing mnemonic (no-broadcast path), `invalid_*_request` |
| Invalid contract initialization | **Yes** | `init_game_failed`, `open_payments_failed`, artifact empty at startup |
| Provider/RPC failure | **Yes** | `TonCenter HTTP *`, errors in `tonDeployDebug.tonCenterStatus/Response` |
| Network timeout | **Yes** | `deploy_timeout`, `escrow_activation_timeout`, `deployer_seqno_confirmation_timeout` |
| Wallet/deployer issue | **Yes** | Seqno never advances, insufficient balance (RPC error text in debug) |
| Contract rejection | **Possible** | BOC send rejected by TonCenter (`Failed to unpack Message`, etc.) |
| Gas/value problem | **Possible** | Fixed 0.05 TON; insufficient deployer balance → RPC error |
| Unknown | Fallback | `deploy_failed` in adapter catch masks inner error — **use `tonDeployDebug`** |

**Do not assign a specific category to ROOM_bXwC / ROOM_HxV5 without archive `reason` / `tonDeployDebug`.**

## 7. Mobile browser correlation

```
Client-dependent: NO
```

**Reason:**

| Deploy input | Source |
|--------------|--------|
| Contract snapshot / player wallets | **Server** `sessionWalletStore` (already set at `WALLET_CONNECT_REPORT` before deploy) |
| Oracle / owner / deployer | **Server** env + `OwnerConfiguration` |
| Deploy / init / open transactions | **Server** `TonGameContractAdapter` + TonCenter RPC |
| Browser / TonConnect client | Used only for **wallet connect** and later **STAKE** — deploy runs **before** `PAYMENT_REQUEST` |

Opera/Mi Browser correlates with **which human/device** was in the session, not with deploy execution. All three devices could share one failing server deploy for the room.

Wallet connect from mobile browser **must succeed** before `PAYMENT_CONNECTION_READY`; that data is already on the server when deploy starts.
