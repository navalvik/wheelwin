# R17.9T.6-D2 — Runtime Engine Restoration Implementation

Date: 2026-08-22

Task: Implement the controlled sub-stage (D2) of R17.9T.6-D — Runtime Engine Restoration: additive silent attach APIs on the existing runtime engine owners, following the completed D2 pre-implementation audit as the architectural source of truth.

## 1. Scope

This sub-stage implemented ONLY additive runtime-engine recovery capabilities on the six existing engine owners:

1. `ConfigurationEngine.attachConfiguration({ gameId, roomId, configuration, configurationHash })`
2. `GameStateEngine.attachState({ gameId, currentState, enteredAt, previousState, history })`
3. `GameClockEngine.attachClock(clockState, { arm: false })` + `GameClockEngine.armRecoveredClock(gameId)`
4. `PhysicsEngine.attachSimulation({ gameId, parameters, runtime, commandLog }, { emitEvents: false })`
5. `InputAuthority.attachRegistry({ gameId, playerIds, players, speedInputClosed, commandQueue, acceptedCommands, sequenceNumber })`
6. `WinnerEngine.attachResult(result)` + `WinnerEngine.restoreResult(gameId)`

This stage does NOT implement RecoveryOrchestrator, SERVER_RESTART orchestration, recovery record production wiring, financial recovery, reconnect integration, or client behavior. End-to-end restart recovery is NOT implemented or claimed.

## 3. Architecture Findings

All six engines follow the same conventions: ES classes with `{ logger, eventBus, ... }` constructors, in-memory `Map` registries keyed by exact `gameId`, error handling via `logger.error(...)` + return `null` (no exceptions from public APIs except the existing validation-error paths). All D2 APIs follow this convention: validate everything first, mutate registries only after full validation, return `null` on failure, never partially populate state.

The configuration hash convention matches `RecoveryDataPersistence`: SHA-256 over `stableStringify(configuration)` (`computePayloadChecksum` equivalent implemented locally via `createHash("sha256")` + imported `stableStringify`).

## 4. Lifecycle Flow

```
attachConfiguration   -> validate ids/hash/structure -> deep-freeze detached copy -> _configurations.set -> NO event
attachState           -> validate state/timestamps/history -> _states.set -> NO event
attachClock(arm:false)-> validate fields/timers/expiry -> _clocks.set (running=false, timeoutHandle=null) -> NO event
armRecoveredClock     -> refuse expired/paused/RESULT/duplicate -> running=true + exactly one setTimeout -> NO lifecycle event
attachSimulation      -> restrict to CREATED | STOPPED -> validate finite/zero-motion -> _simulations.set (physicsStoppedEmitted=true for STOPPED) -> NO event, NO SimulationLoop registration
attachRegistry        -> validate playerIds vs PlayerManager + empty queues + sequence 0 -> build registry atomically -> _registries.set -> NO event, NO PlayerManager mutation
attachResult          -> require configuration -> validate winner against configuration -> freeze -> _results.set -> NO event
restoreResult         -> require configuration + STOPPED physics -> silent deterministic recompute -> resolvedAt:null (not invented) -> _results.set -> NO event
```

## 6. Exact APIs Added

### ConfigurationEngine.attachConfiguration({ gameId, roomId, configuration, configurationHash })
Validates: gameId, roomId, configuration object, hash string, `configuration.gameId === gameId`, `configuration.metadata.roomId === roomId`, SHA-256 hash of complete configuration, structural validation via existing `validateConfiguration`. Deep-freezes a detached (`JSON.parse(JSON.stringify(...))`) copy before storing. Emits nothing; calls no random service.
Duplicates: absent → attach; equivalent (same computed hash of existing) → idempotent success returning existing frozen object; conflicting → fail closed (`null`). Failure leaves neither `_configurations` nor `_economies` populated.

### GameStateEngine.attachState({ gameId, currentState, enteredAt, previousState = null, history = [] })
Validates: gameId, `isValidGameState(currentState)`, finite positive `enteredAt`, optional valid `previousState`, array history with valid entries. Attaches directly without transition replay. No `GAME_STATE_CHANGED`, no `GAME_STATE_REJECTED`.
Duplicates: absent → attach; same currentState → idempotent snapshot; conflicting → fail closed. Failed attachment leaves prior registry state untouched.

### GameClockEngine.attachClock(clockState, { arm = false })
Validates: clockState object, gameId, phase ∈ CLOCK_PHASE_SEQUENCE, finite startedAt/phaseStartedAt/serverTimestampAtCheckpoint, boolean paused/awaitingResultActivation/resultPhaseStarted, non-negative totalPausedMs, timer definition exists for phase (from persisted `frozenTimers` when supplied, else catalog snapshot), and for unpaused phases that the deadline has NOT already expired at checkpoint time (expired → fail closed).
Creates record with `running=false`, `timeoutHandle=null`; preserves authoritative persisted fields (currentPhase, startedAt, phaseStartedAt, paused, totalPausedMs, awaitingResultActivation, resultPhaseStarted, frozenTimers); computes `phaseEndsAt = phaseStartedAt + duration` and remaining relative to checkpoint. ATTACH ≠ ARM: no timeout, no events, no startClock call.
Duplicates: absent → attach; semantically equivalent (phase/startedAt/phaseStartedAt/paused/totalPausedMs equal) → idempotent; conflicting → fail closed.

### GameClockEngine.armRecoveredClock(gameId)
Arms only a previously attached eligible clock: refuses missing clock, already-running, duplicate timeout handle, paused clocks, RESULT phase (terminal-invalid), missing timer definition, and expired deadlines (`remaining <= 0`). On success sets `running=true` and creates exactly one `setTimeout`. Emits no lifecycle events (no CLOCK_STARTED, no phase-started).

### PhysicsEngine.attachSimulation({ gameId, parameters = {}, runtime, commandLog = [] }, { emitEvents = false })
Restricts accepted shapes to CREATED (pre-motion, all angles/velocities/acceleration zero) or STOPPED (finite final angles required, terminal velocities/acceleration must be zero). Rejects RUNNING/BRAKING under the current contract. Validates all numeric runtime fields finite where present. Sets `physicsStoppedEmitted=true` for STOPPED so later cleanup cannot emit a false PHYSICS_STOPPED. Never emits PHYSICS_STARTED/UPDATED/BRAKING/STOPPED; never registers SimulationLoop membership. Duplicate: absent → attach; equivalent (state+angles) → idempotent; conflicting → fail closed. Failure leaves no stale simulation.

### InputAuthority.attachRegistry({ gameId, playerIds, players = null, speedInputClosed = false, commandQueue = [], acceptedCommands = [], sequenceNumber = 0 }
Validates: gameId, non-empty playerIds array, no duplicate IDs, every playerId present in the already-attached PlayerManager identity boundary (`hasPlayer`), empty commandQueue, empty acceptedCommands, integer sequenceNumber ≥ 0. Builds the whole registry (default player states via existing `createDefaultPlayerInputState`) before insertion — atomic. Does NOT mutate PlayerManager, does NOT call registerPlayers/registerPlayer, emits no input events. `speedInputClosed` optionally restores the speed-closed flag. Duplicate: absent → attach; equivalent player set → idempotent; conflicting → fail closed. Failure leaves no partial registry.

### WinnerEngine.attachResult(result)
Terminal-only support: requires the game's configuration to already be attached; validates winning sector/player structure and that the winner exists in configuration (existing `_validateResult`). Freezes via existing `deepFreezeResult`. Emits no WINNING_SECTOR_RESOLVED / GAME_RESULT_READY / GAME_RESULT_REMOVED. Duplicate: absent → attach; equivalent (winnerPlayerId + winnerSectorIndex) → idempotent; conflicting → fail closed.

### WinnerEngine.restoreResult(gameId)
Silent deterministic recomputation from exact attached configuration + terminal STOPPED physics using the existing resolvers (`_readResolutionInputs`, SectorResolver, PlayerResolver). Does NOT call the event-emitting `resolveResult()`. Historical `resolvedAt` is NOT persisted in the current contract and is NOT invented: the restored result carries `resolvedAt: null`, making the limitation explicit. Duplicate: existing result returned as-is (idempotent). Any failure leaves `_results` empty.

## 7. Validation Rules Summary

| Engine | Identity | Content | Expiry/Terminal | Duplicate policy |
|---|---|---|---|---|
| Configuration | gameId, roomId, config.gameId, config.metadata.roomId | SHA-256 hash, structure via validateConfiguration | n/a | idempotent-equivalent / conflict-fail-closed |
| GameState | gameId | valid state, timestamps, history entries | n/a | idempotent-same-state / conflict-fail-closed |
| Clock | gameId | phase ∈ sequence, finite times, boolean flags, timer definition | unpaused deadline must not be expired at checkpoint; arming refuses expired/paused/RESULT | idempotent-equivalent / conflict-fail-closed |
| Physics | gameId | finite numerics; CREATED ⇒ zero motion; STOPPED ⇒ finite angles + zero motion | RUNNING/BRAKING rejected | idempotent-equivalent / conflict-fail-closed |
| InputAuthority | gameId, playerIds ⊆ PlayerManager | no duplicates, empty queues, sequence ≥ 0 | active SPEED/BRAKE restoration rejected by empty-queue policy | idempotent-equivalent-set / conflict-fail-closed |
| Winner | gameId | winner ∈ configuration players; physics STOPPED for restore | RESULT-only restoration | idempotent-equivalent / conflict-fail-closed |

## 8. Event Isolation Behavior

No D2 attachment API emits any normal gameplay lifecycle event. Verified by test counters subscribed to 30 lifecycle event types (CONFIGURATION_READY/REMOVED, GAME_STATE_CHANGED/REJECTED, CLOCK_STARTED/PAUSED/RESUMED/STOPPED, PHASE_TIMEOUT, all phase-started/completed events, PHYSICS_STARTED/UPDATED/BRAKING/STOPPED, PLAYER_INPUT_ACCEPTED/REJECTED, WINNING_SECTOR_RESOLVED, GAME_RESULT_READY/REMOVED): zero emissions during all attachment operations. Legitimate teardown noise from normal `shutdown()`/`removeClock()` paths is excluded from the isolation assertions (counters reset around teardown-only steps).

## 11. Blockers / Limitations (explicit, not silently hidden)

1. **SELF_TEST / SPEED / BRAKE remain unrecoverable.** Physics `attachSimulation` rejects RUNNING/BRAKING; InputAuthority rejects non-empty queues; no SimulationLoop registration occurs. Confirmed by tests.
2. **Paused-clock exactness gap.** The contract lacks `pauseStartedAt`/persisted remaining time. D2 does not invent pause timing: paused clocks can be attached unarmed but `armRecoveredClock` refuses to arm paused clocks; exact paused resume requires a later contract amendment.
3. **Winner historical `resolvedAt` gap.** Not persisted; `restoreResult` exposes `resolvedAt: null` rather than inventing it. A complete persisted result may later be supplied via `attachResult`.
4. **Historical economy gap.** `attachConfiguration` does not populate `_economies`; deriving economy from possibly-changed catalog rules would invent financial-adjacent state. Left for a later cross-domain decision.
5. **End-to-end SERVER_RESTART recovery is NOT implemented.** No RecoveryOrchestrator, no production recovery-record write/update wiring, no candidate discovery. Production currently writes no recovery records (per D2 audit), so no real restart candidate can invoke these APIs yet.
6. **Expired unpaused deadlines fail closed** at both attach (checkpoint-relative) and arm (wall-clock-relative) boundaries; catch-up policy belongs to later orchestration.
