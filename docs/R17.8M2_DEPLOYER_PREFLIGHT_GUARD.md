# R17.8M.2 — Deployer Balance Preflight Guard

**Date:** 2026-08-14  
**Depends on:** R17.8M.1 (admin deployer wallet observability)  
**Production issue addressed:** `deployer_seqno_confirmation_timeout` caused by insufficient deployer balance (~0.007 TON vs 0.05 TON deploy value)

---

## 1. Summary

Before broadcasting a GameEscrow deploy transaction, `TonGameContractAdapter._broadcastDeploy()` now runs a **deployer wallet balance preflight**. If the deployer balance is below the centralized reserve threshold, deploy fails immediately with `INSUFFICIENT_DEPLOYER_BALANCE` — **without** calling `sendBoc()` or waiting for seqno confirmation.

---

## 2. Flow

```text
BEGIN_DEPLOY (GameContractManager)
        ↓
TonGameContractAdapter.deployContract()
        ↓
_broadcastDeploy()
        ↓
checkDeployerBalancePreflight()
        ↓
balance >= DEPLOYER_MIN_BALANCE_REQUIRED (0.2 TON)
        ↓
_sendOracleMessage() → sendBoc() → existing deploy flow

OR

balance < 0.2 TON
        ↓
return { ok: false, reason: INSUFFICIENT_DEPLOYER_BALANCE }
        ↓
GAME_CONTRACT_DEPLOY_FAILED
```

**Unchanged:** INIT_GAME, OPEN_PAYMENTS, SETTLE, and other `_sendOracleMessage` operations do not run deploy preflight.

---

## 3. Implementation

| Component | Path |
|-----------|------|
| Reserve constant | `server/payment/ton/deployerBalancePolicy.js` |
| Preflight helper | `server/payment/ton/checkDeployerBalancePreflight.js` |
| Guard hook | `TonGameContractAdapter._broadcastDeploy()` |
| Observability alignment | `evaluateDeployerWalletReadiness.js` uses same 0.2 TON READY threshold |

### Centralized threshold

```js
DEPLOYER_MIN_BALANCE_REQUIRED_TON = "0.2"
DEPLOYER_MIN_BALANCE_REQUIRED_NANO = toNano("0.2")
```

Covers deploy value (0.05 TON), fees, initialization, and safety buffer.

### Wallet identity

Reuses `deriveDeployerWalletIdentity()` from in-memory `tonConfig.deployerMnemonic` — never logs or returns mnemonic/keys.

### Balance lookup

Uses `TonService.getBalance()` when available; falls back to `getAccount().balance` for legacy/mock services.

---

## 4. Failure behavior

When preflight fails:

| Field | Value |
|-------|--------|
| Adapter result | `{ ok: false, reason: "INSUFFICIENT_DEPLOYER_BALANCE", diagnostics: {...} }` |
| Manager event | `GAME_CONTRACT_DEPLOY_FAILED` |
| Downstream | `PAYMENT_SESSION_FAILED` → room teardown (existing path) |

**Safe diagnostics included:**

- `availableBalance`
- `requiredBalance` (0.2 TON)
- `deployerAddress`
- `network`

**Never included:** mnemonic, privateKey, secret, seed.

---

## 5. Logging

Structured logger events (no secrets):

| Event | When |
|-------|------|
| `GAME_CONTRACT_DEPLOY_PREFLIGHT_STARTED` | Before balance check |
| `GAME_CONTRACT_DEPLOY_PREFLIGHT_PASSED` | Balance sufficient |
| `GAME_CONTRACT_DEPLOY_PREFLIGHT_FAILED` | Balance insufficient |

Fields: `deployerAddress`, `balance`, `requiredBalance`, `network`, `reason` (on failure).

Ton deploy debug stages also record preflight start/pass/fail for `/console/blockchain` visibility.

## 6. Security

- Mnemonic remains Railway ENV only (`TON_DEPLOYER_MNEMONIC`).
- Preflight is read-only — no wallet mutation.
- No new admin controls or secret storage.

## 8. Remaining limitations

- **Threshold is static** — 0.2 TON reserve; not dynamically computed from deploy value + live fee estimates.
- **Deploy-only** — INIT_GAME / OPEN_PAYMENTS still rely on seqno confirmation path if balance drops mid-session.
- **No automatic funding** — operators must fund deployer wallet manually; R17.8M.1 panel shows readiness.
- **RPC dependency** — if balance lookup fails, deploy returns error (does not proceed blindly).
