# R17.8M.0 — Admin TON Deployer Wallet Observability Audit + Implementation Plan

**Mode:** Audit + implementation planning only (no code changes)  
**Date:** 2026-08-14  
**Depends on:** R17.8L (deployer wallet state investigation)  
**Production issue:** `deployer_seqno_confirmation_timeout` caused by **insufficient deployer balance** (~0.007 TON vs 0.05 TON deploy value)

---

## 1. Executive summary

WheelWin already **derives** the deployer wallet from `TON_DEPLOYER_MNEMONIC` at startup and logs a **Railway-visible** identity snapshot (`TON_WALLET_IDENTITY_DEBUG`), but this data is **not exposed** in the `/debug` Developer Console UI. Operators must SSH/Railway-log to verify balance before deploy.

**Recommendation:** Add an **Administrator-only** read-only panel under `/debug` backed by a new **`GET /console/ton/deployer-wallet`** endpoint that re-derives identity from in-memory config, live-queries balance/seqno via `TonService`, and returns operational status — **never** the mnemonic or keys.

## 2. Current deployer wallet architecture

### 2.1 Derivation chain

```text
Railway ENV: TON_DEPLOYER_MNEMONIC
        ↓
loadTonConfig()  (server/config/ton.js)
        ↓
tonConfig.deployerMnemonic  (in-memory only; never persisted)
        ↓
deriveDeployerWalletIdentity({ mnemonic, network })
        ↓
WalletContractV4.create({ workchain: 0, publicKey })
        ↓
deployerAddress (bounceable friendly)
```

| Property | Value |
|----------|--------|
| **File** | `server/payment/ton/deriveDeployerWalletIdentity.js` |
| **Function** | `deriveDeployerWalletIdentity({ mnemonic, network })` |
| **Input** | `TON_DEPLOYER_MNEMONIC` (24-word phrase from env) |
| **Wallet version** | `WalletContractV4R2` (`WalletContractV4` from `@ton/ton`) |
| **Wallet ID** | `698983191` (library default for V4R2) |
| **Workchain** | `0` |
| **Derived address (production)** | `EQB83s9XMOMseDFxyXxj4hrC0sS4FB4xhdNiUPkl_3zx3PDQ` |
| **Active network** | `testnet` (from `TON_NETWORK`; mainnet account for same mnemonic is uninitialized) |

**Deploy usage:** `TonGameContractAdapter._sendOracleMessage` derives the same wallet inline from `this._tonConfig.deployerMnemonic` before each DEPLOY / INIT / OPEN send.

**Settlement usage:** `app._resolveDeployerWalletAddress()` derives address for `ContractSettlementManager` tx watches.

### 2.2 ENV → address confirmation

| Step | Mechanism |
|------|-----------|
| Mnemonic loaded | `loadTonConfig()` → `deployerMnemonic` |
| Address derived | `deriveDeployerWalletIdentity` |
| Optional pin | `TON_DEPLOYER_EXPECTED_ADDRESS` or network profile `deployerExpectedAddress` |
| Startup validation | `_runTonWalletIdentityDiagnostics()` → `assertDeployerWalletMatchesExpected` — **throws on mismatch** when expected address is set |
| Active deploy address | Same derived address used by `TonGameContractAdapter` |

**Confirmed:** ENV mnemonic → derived address **is** the active deployer address. R17.8L archives show `tonDeployDebug.deployerAddress` matching startup identity.

### 2.3 Existing observability (not in `/debug` UI)

| Artifact | Location | When updated | Exposed via API? |
|----------|----------|--------------|------------------|
| `TON_WALLET_IDENTITY_DEBUG` | `server/diagnostics/TonWalletIdentityDebug.js` | Server startup | **No** (stdout / Railway logs only) |
| `R7.70 WALLET READINESS` | `server/diagnostics/TonTestnetWalletReadiness.js` | Startup probe | **No** |
| `TON_MAINNET_READINESS` | `server/diagnostics/TonMainnetReadiness.js` | Startup (mainnet path) | **No** |
| `tonDeployDebug` | `DeployPipelineForensics.js` | Last deploy attempt | **Yes** — `/console/blockchain` (last failure snapshot, not live wallet) |
| CLI scripts | `check-testnet-wallet-readiness.js`, `check-mainnet-readiness.js` | Manual | N/A |

**Gap:** Startup balance is **stale immediately** after funding. No console refresh. `BlockchainStatusPanel` shows **last deploy debug seqno**, not live chain seqno.

## 4. Security requirements

### 4.1 MUST NOT

| Rule | Reason |
|------|--------|
| Store mnemonic in DB | Single source of truth is Railway ENV |
| Return mnemonic in API/UI | Secret exfiltration |
| Log mnemonic in deploy debug or new endpoint | Railway/log leakage |
| Browser-side derivation from mnemonic | Mnemonic must never reach client |
| UI to edit `TON_DEPLOYER_MNEMONIC` | ENV rotation is Railway-only |
| UI wallet switching | Network/wallet selection stays ENV + restart |

### 4.2 SHOULD

| Rule | Implementation hint |
|------|---------------------|
| Derive identity server-side only | Reuse `deriveDeployerWalletIdentity` |
| Live RPC for balance/seqno | `TonService.getBalance` / `getSeqno` on request |
| Administrator-only endpoint | `createAdministratorAuthMiddleware` |
| Redact secrets from responses | Explicit allow-list DTO; never spread `tonConfig` |
| Audit denied access | Reuse `authService.auditPermissionDenied` |
| Rate-limit or cache lightly | Optional 5–10 s cache to avoid RPC spam (panel poll) |

### 4.3 Risk review

| Risk | Severity | Mitigation |
|------|----------|------------|
| Admin account compromise exposes deployer address/balance | Medium | Expected; no keys returned; standard admin hygiene |
| Viewer role sees funding state | Low–Med | **Restrict endpoint to Administrator** |
| Stale startup snapshot misleads ops | High (R17.8L) | **Live query** on each panel refresh |
| Error messages leak mnemonic fragments | High | Never include env values in errors |
| `/console/blockchain` already exposes deployer address from last deploy | Low | Last-attempt only; new panel adds live state |
| Legacy `/debug/*` without auth if `showDebugPanel` | Medium | Out of scope for M.1; do not add deployer data there |

## 5. Required observability fields (safe DTO)

### 5.1 Identity

| Field | Source |
|-------|--------|
| `network` | `tonConfig.network` |
| `walletType` | `identity.walletContractType` → `WalletContractV4R2` |
| `walletId` | `identity.walletId` |
| `workchain` | `identity.workchain` |
| `deployerAddress` | `identity.address` |
| `deployerAddressNonBounceable` | `identity.addressNonBounceable` (optional) |
| `endpointHost` | Parsed from `tonConfig.endpoint` (host only, no API key) |

### 5.2 Blockchain state (live)

| Field | Source |
|-------|--------|
| `balanceNano` | `TonService.getBalance` |
| `balanceTon` | `Number(nano) / 1e9` |
| `seqno` | `TonService.getSeqno` |
| `accountState` | `TonService.getAccount` → `state` (`active` / `uninitialized`) |
| `lastCheckedAt` | `Date.now()` at query time |
| `balanceError` | RPC error message if query failed |
| `seqnoError` | RPC error message if query failed |

### 5.3 Configuration validation

| Field | Source |
|-------|--------|
| `mnemonicConfigured` | `Boolean(tonConfig.deployerMnemonic)` — **never** the value |
| `deployMode` | `tonConfig.deployMode` (`live` / `stub`) |
| `expectedAddress` | `tonConfig.deployerExpectedAddress` |
| `identityMatch` | `tonAddressesEqual(derived, expected)` or `null` if no pin |
| `walletDerivationStatus` | `OK` / `ERROR` / `NOT_CONFIGURED` |
| `addressMatchStatus` | `MATCH` / `MISMATCH` / `UNPINNED` |

### 5.4 Operational readiness (derived, no secrets)

Based on R17.8L findings and existing `evaluateTonTestnetWalletReadiness`:

| Field | Logic |
|-------|--------|
| `deployMessageValueTon` | `0.05` (constant from deploy adapter; or read from config if later parameterized) |
| `minimumBalanceTonRecommended` | `0.2` (operational buffer; document in panel) |
| `readinessStatus` | `READY` / `WARNING` / `ERROR` |
| `readinessReasons[]` | e.g. `"balance below deploy message value"`, `"balance below 0.1 TON threshold"`, `"mnemonic not configured"`, `"address mismatch"` |

**Status rules (proposal):**

| Status | Conditions |
|--------|------------|
| **ERROR** | Mnemonic missing; derivation error; address mismatch; account uninitialized on active network; balance &lt; deploy message value (0.05 TON) |
| **WARNING** | Balance ≥ 0.05 but &lt; 0.2 TON; RPC errors with cached startup values unavailable |
| **READY** | Mnemonic OK, address match OK (if pinned), balance ≥ 0.2 TON, seqno readable |

### 5.5 Explicitly excluded from API response

```text
mnemonic, privateKey, secretKey, seed, TON_API_KEY,
TON_DEPLOYER_MNEMONIC, DEVELOPER_AUTH_SECRET, any env secret
```

## 6. Mainnet migration verification flow

```text
1. Operator updates Railway ENV:
     TON_NETWORK=mainnet
     TON_DEPLOYER_MNEMONIC=<mainnet mnemonic>   (or same mnemonic if shared — verify policy)
     TON_DEPLOYER_EXPECTED_ADDRESS=<mainnet deployer EQ...>
     TON_MAINNET_ORACLE_ADDRESS=<...>
     TON_ENDPOINT=<mainnet TonCenter URL>

2. Redeploy / restart backend

3. Startup guards run:
     _runTonWalletIdentityDiagnostics()
     _runTonMainnetReadinessDiagnostics()  (when network=mainnet)

4. Operator opens /debug → Administrator login → TON Deployer Wallet panel

5. Verify:
     network = mainnet
     deployerAddress = expected mainnet EQ...
     identityMatch = MATCH
     accountState = active
     balanceTon = sufficient (>> 0.05 TON)
     seqno = readable integer
     readinessStatus = READY

6. No UI action required — ENV is sole source of truth
```

**Panel copy (proposal):** “Wallet is controlled by Railway environment variables. Changing network or mnemonic requires a server restart.”

## 12. R17.8M.1 — Implementation (completed)

**Date:** 2026-08-14  
**Commit:** `R17.8M.1 Admin TON deployer wallet observability`

### 12.1 Backend

| Component | Path |
|-----------|------|
| Readiness evaluator | `server/console/projectionBuilders/evaluateDeployerWalletReadiness.js` |
| Status builder | `server/console/projectionBuilders/buildDeployerWalletStatus.js` |
| Projection adapter | `DeveloperConsoleProjectionService.buildDeployerWalletStatus()` |
| HTTP route | `GET /console/ton/deployer-wallet` in `registerDeveloperConsoleRoutes.js` |

**Flow:**

```text
runtimeConfig.ton.deployerMnemonic
        ↓
deriveDeployerWalletIdentity()   (existing; never returns keys)
        ↓
TonService.getBalance(address)
TonService.getSeqno(address)
        ↓
evaluateDeployerWalletReadiness(balanceNano)
        ↓
Safe JSON DTO (no mnemonic / keys)
```

**Readiness thresholds:**

| Status | Condition | `reason` |
|--------|-----------|----------|
| ERROR | balance &lt; 0.05 TON | `INSUFFICIENT_DEPLOYER_BALANCE` |
| WARNING | 0.05 ≤ balance &lt; 0.2 TON | `LOW_DEPLOYER_RESERVE` |
| READY | balance ≥ 0.2 TON | `DEPLOYER_WALLET_READY` |

### 12.2 API

```
GET /console/ton/deployer-wallet
Authorization: Bearer <developer-jwt>
```

| Caller | Response |
|--------|----------|
| Administrator | `200` + deployer wallet DTO |
| Viewer | `403 Forbidden` |
| Unauthenticated | `401 Unauthorized` |

**Example response:**

```json
{
  "network": "testnet",
  "walletType": "WalletContractV4R2",
  "walletId": 698983191,
  "address": "EQ...",
  "balance": "0.007",
  "seqno": 100,
  "lastCheckedAt": "2026-08-14T08:00:00.000Z",
  "readiness": {
    "status": "ERROR",
    "reason": "INSUFFICIENT_DEPLOYER_BALANCE",
    "message": "Deployer wallet balance is insufficient"
  }
}
```

### 12.3 Security model

- **Administrator-only** via `createAdministratorAuthMiddleware` on the route.
- Response is an **allow-list DTO** — no `mnemonic`, `privateKey`, `secret`, or `seed`.
- Mnemonic remains **Railway ENV only** (`TON_DEPLOYER_MNEMONIC`); never logged or returned.
- No wallet switching, mnemonic input, or database storage added.

### 12.4 Frontend

| Component | Path |
|-----------|------|
| Panel | `client/src/console/panels/DeployerWalletPanel.jsx` |
| API client | `fetchDeployerWalletStatus()` in `developerAuthApi.js` |
| Navigation | `ton-deployer-wallet` section in `consoleSections.js` |
| Router | `DeveloperConsole.jsx` case handler |

**UI sections:** Identity (network, wallet type, wallet ID, address), Blockchain State (balance, seqno, last checked), Readiness (status + message with tone styling).

Viewer accounts see an **Administrator access required** empty state; the API returns `403` if called directly.

### 12.5 Tests

File: `server/tests/deployerWalletObservability.test.js`

| Test | Result |
|------|--------|
| A — Admin access (`GET /console/ton/deployer-wallet` as admin) | `200 OK` |
| B — Non-admin access (viewer) | `403 Forbidden` |
| C — Secret protection (no mnemonic/privateKey/secret/seed in response) | Pass |
| D — Readiness: 0.007 TON → ERROR, 0.1 TON → WARNING, 0.5 TON → READY | Pass |

Run: `node server/tests/deployerWalletObservability.test.js` (also included in `npm test`).

### 12.6 Remaining limitations

- **No pre-deploy guard** — low balance still fails at deploy time until R17.8M.2.
- **No auto-refresh** — panel loads on mount; manual navigation refresh required (10 s polling deferred).
- **TonService dependency** — if RPC is down, route returns `500`; balance/seqno require live chain access.
- **Startup-only diagnostics unchanged** — `TON_WALLET_IDENTITY_DEBUG` remains log-only.

This directly addresses R17.8L: operators can now see **ERROR** readiness when deployer balance is below 0.05 TON before attempting GameEscrow deploy.
