# R17.9T.6-D3 — RecoveryOrchestrator Implementation

Date: 2026-08-22

Task: Implement the main R17.9T.6-D3 RecoveryOrchestrator — coordination of one persisted recovery candidate at a time using the completed D1 identity attach APIs, D2 runtime engine attach APIs, and D3 silent detach primitives.

## 1. Scope

Implemented `server/recovery/RecoveryOrchestrator.js` (new file) providing:

- candidate discovery via existing `RecoveryDataPersistence` APIs;
- candidate classification over existing contract fields only;
- pre-mutation candidate validation;
- aggregate construction via existing constructors;
- ordered D1/D2 attach invocation with silent rollback on any failure;
- cross-engine consistency validation;
- idempotency / duplicate-conflict handling;
- clock arming strictly last for eligible non-expired unpaused pre-game candidates;
- explicit per-candidate results and `recoverAll()` aggregate summary.

Plus focused tests (`server/tests/recoveryOrchestrator.r179t6d3.test.js`) and this report.

## 2. RecoveryOrchestrator API

```js
new RecoveryOrchestrator({
    logger, recoveryDataPersistence,
    roomManager, playerManager, gameManager,
    configurationEngine, gameStateEngine, gameClockEngine,
    physicsEngine, inputAuthority, winnerEngine
})

recoverCandidate(recoveryRecord) // record envelope or bare payload
    -> { status, classification, recoveryRecordId, gameId, roomId,
         failedStep?, reason }

recoverAll()
    -> { results: [...], summary: { total, success, alreadyRecovered,
         skippedNotRecoverable, skippedFinancialOnly, skippedAlreadyTerminal,
         failed } }
```

Result statuses exported as `RECOVERY_RESULT_STATUS`: SUCCESS, ALREADY_RECOVERED, SKIPPED_NOT_RECOVERABLE, SKIPPED_FINANCIAL_ONLY, SKIPPED_ALREADY_TERMINAL, FAILED_INVALID_RECORD, FAILED_IDENTITY, FAILED_CONFIGURATION, FAILED_STATE, FAILED_CLOCK, FAILED_EXPIRED, FAILED_PHYSICS, FAILED_INPUT, FAILED_WINNER, FAILED_CONSISTENCY, FAILED_ATTACH, FAILED_ROLLBACK.

No other public helpers are exposed; classification/validation/rollback are internal.

## 3. Candidate Discovery

`recoverAll()` obtains candidates exclusively through `RecoveryDataPersistence.listRecoveryRecords()`. No direct filesystem access, no synthetic candidates, no persistence writes. Empty/absent records → explicit empty result `{ results: [], summary: { total: 0, ... } }`. Discovery failure is reported with `discoveryFailed: true` without throwing.

## 4. Candidate Classification

Pure function over existing payload/envelope fields:

| Class | Criteria |
|---|---|
| INVALID | fails `validateRecoveryRecord` (checksum/version/structure/hash) |
| ALREADY_RECOVERED | runtime check: equivalent room+game+players already present |
| ALREADY_TERMINAL | `gameStatus === FINISHED \| DESTROYED` |
| FINANCIAL_ONLY | envelope status ∈ {SETTLED, FAILED_CLOSED, TERMINAL} |
| EXPIRED | unpaused PRE_GAME_READY/READY with `phaseStartedAt + timers[phase].durationMs <= serverTimestampAtCheckpoint` |
| NOT_RECOVERABLE | SELF_TEST / SPEED / BRAKE; paused clock (exact pause timing not persisted); unsupported gameState |
| RECOVERABLE | PRE_GAME_READY / READY / RESULT (RESULT requires terminal STOPPED physics) |

No new gameplay states, no new persistence fields.

## 5. Aggregate Construction

Existing constructors only; no ID generation; no normal create APIs:

- Room: `new Room({ roomId, createdAt: null, status: FULL, maxPlayers: 3, players })` — players ordered by persisted `playerIndex`; `createdAt` is not persisted and is NOT invented.
- Players: `new PlayerIdentity({...verbatim persisted fields..., createdAt: null})` + `new PlayerRuntime({ roomId, gameId, lastSeen: null })` wrapped as `{ playerId, playerIndex, identity, runtime }` (authoritative D1 object-based shape).
- Game: `new Game({ gameId, roomId, createdAt: null, status: gameStatus, players, metadata: {} })`.

If a constructor-required value were unavailable in the contract, the candidate is stopped with an explicit failure — no invented values anywhere.

## 6. Attach Order

1. Validate record (persistence-level when envelope present).
2. Classify.
3. Duplicate detection (before any mutation).
4. Pre-mutation validation (identity, players, configuration hash/seed/version/player-set, state, clock validity/expiry, physics shape).
5. Construct aggregates.
6. `RoomManager.attachRoom(room)`
7. `PlayerManager.attachPlayer(player)` ×3
8. Validate playerIndex/order against Room ordering
9. `GameManager.attachGame(game)`
10. `ConfigurationEngine.attachConfiguration({ gameId, roomId, configuration, configurationHash })`
11. `GameStateEngine.attachState({ gameId, currentState, enteredAt: serverTimestampAtCheckpoint, previousState: null, history: [] })`
12. `GameClockEngine.attachClock(clockState, { arm: false })` — PRE_GAME_READY/READY only
13. `InputAuthority.attachRegistry({ gameId, playerIds, commandQueue: [], acceptedCommands: [], sequenceNumber: 0 })` — PRE_GAME_READY/READY only
14. `PhysicsEngine.attachSimulation({ gameId, runtime, commandLog: [] }, { emitEvents: false })` — CREATED for pre-game, STOPPED with exact final angles for RESULT
15. `WinnerEngine.restoreResult(gameId)` — RESULT only, silent deterministic recompute; validated against `payload.winnerId` when non-null
16. Cross-engine consistency validation
17. `GameClockEngine.armRecoveredClock(gameId)` — strictly last

No SimulationLoop registration at any point.

## 7. Cross-Engine Validation

Read-only checks after attachment: room/game identity and membership vs ordered player list; configuration identity (gameId/metadata.roomId); GameState equals persisted phase; clock phase equals persisted phase (pre-game); physics state CREATED/STOPPED per class; input registry presence (pre-game); winner result presence (RESULT). Any conflict → fail closed + full rollback. No automatic repair.

## 8. Clock Policy

`attachClock` always unarmed during reconstruction. Arming occurs only after all components attached and consistency validated, only for eligible unpaused non-expired PRE_GAME_READY/READY clocks. Expired candidates fail closed at classification/pre-validation (`FAILED_EXPIRED`) before any mutation; arming refusal also yields `FAILED_EXPIRED` with full rollback. Paused clocks fail closed (contract lacks `pauseStartedAt`/persisted remaining time); no pause duration is ever invented.

## 9. RESULT Recovery

Requires valid configuration, RESULT state, terminal STOPPED physics with finite final angles. Winner restored silently via `restoreResult` (historical `resolvedAt` NOT persisted in contract → exposed as `null`, never invented). No ResultActivation, no settlement, no payment, no result/winner events, no PaymentSessionManager interaction, no clock attach/arming, no input registry.

## 10. Silent Rollback

Reverse order of successful attachment: winner (`detachResult`) → physics (`removeSimulation`, silent for CREATED/STOPPED shapes) → input (`removeGame`) → clock (`removeClock`, silent while unarmed) → state (`removeState`) → configuration (`detachConfiguration`) → game (`detachGame`) → players (`detachPlayer`) → room (`detachRoom`). Only approved silent detach APIs and demonstrably silent removals are used. Normal destroy/remove event-emitting methods are never called. Rollback failure → `FAILED_ROLLBACK` with logged residue (inert: nothing was armed/registered).

## 11. Idempotency

- All components present + identity-consistent (+ configuration hash equal if attached) → `ALREADY_RECOVERED`.
- Partial presence → `FAILED_IDENTITY` (conflict), never destroys live runtime.
- Conflicting identity/configuration → `FAILED_IDENTITY`, fail closed.
- Duplicate detection runs before any mutation.

## 12. recoverAll()

Per-candidate independent processing; one failed/skipped candidate cannot corrupt another (each attempt rolls back its own residue; unexpected exceptions are caught per-candidate). Returns per-candidate results plus aggregate counts. Performs NO persistence writes, NO financial actions, NO settlement.

## 13. Event Isolation

Zero normal gameplay lifecycle events during construction, attach, validation, rollback, duplicate detection — verified by test counters over 36 lifecycle event types (including ROOM_CREATED/DESTROYED, GAME_CREATED/DESTROYED, PLAYER_CREATED/REMOVED, CONFIGURATION_READY/REMOVED, CLOCK_*, PHYSICS_*, WINNING_SECTOR_RESOLVED, GAME_RESULT_*). The only CLOCK_STOPPED observed in tests comes from explicit test teardown of armed clocks through normal stop semantics (counters reset around teardown).

## 14. Financial Boundary

The orchestrator preserves reference IDs only (`contractId`, `paymentSessionId`, `snapshotHash`, `winnerId`, `tonNetwork`, `correlationId`). It does not read/write/duplicate financial authority fields, does not call PaymentSessionManager/TonFinancialPersistence write paths, blockchain, settlement, or refund logic. Winner-vs-`payload.winnerId` comparison is payload-local and read-only; live SETTLEMENT cross-check belongs to a later financial reconciliation stage.

## 15. Startup Boundary

No startup integration. `app.js`, bootstrap, Socket.IO, SessionManager, reconnect logic untouched. The orchestrator remains independently callable.

## 21. Remaining Limitations

Explicitly stated:

- **Production startup recovery is NOT integrated** — nothing calls `recoverAll()` at server start; startup gating is a later stage.
- **Production checkpoint/recovery-record writing is NOT implemented** — production code still creates no RECOVERY_DATA records; end-to-end SERVER_RESTART recovery therefore has no real-world candidates yet.
- **Financial recovery is NOT implemented** — no settlement/refund/escrow reconciliation; live SETTLEMENT cross-validation deferred.
- **Reconnect integration is NOT implemented** — recovered candidates are dormant (no sockets/sessions bound; players DISCONNECTED/IDLE).
- **Active SELF_TEST/SPEED/BRAKE recovery remains unsupported** — active physics/input/tick history absent from the contract by design; these phases fail closed permanently under the current contract.
- **SimulationLoop active restoration is NOT implemented** — no loop registration occurs for any candidate.
- **Persistence schema was NOT changed** — `RecoveryDataPersistence` and record types untouched.
- Paused-clock exact resume and historical winner `resolvedAt` remain contract gaps (fail closed / null respectively).
- Historical economy objects are not reconstructed (`_economies` stays empty for recovered games).

End-to-end SERVER_RESTART recovery is NOT claimed as production-ready.
