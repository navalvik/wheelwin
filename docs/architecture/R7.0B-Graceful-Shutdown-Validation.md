## Behavior verified

### Lifecycle transitions

- Startup sets `STARTING`; listen success calls `markRunning()` → `RUNNING`.
- SIGTERM / SIGINT / programmatic `shutdown({ reason })` enter `DRAINING`.
- Drain wait polls in-flight work (setup, games, payments, settlements, teardowns, simulations, recovery, result sessions).
- Idle drain → graceful completion; timeout → forced shutdown warning + teardown.
- Final `markStopped()` → `STOPPED`; logs duration and remaining activity.

### Drain gates

- `RoomManager.createRoom` returns `null` while not accepting new work.
- `SetupSessionLifecycle.createForRoom` rejected while draining.
- Lobby `createRoom` returns `SERVER_DRAINING`.
- In-flight rooms may still complete setup → game → settlement (correctness over uptime).
- New rooms / new setup sessions are rejected.

### Health / readiness

- `/health` includes `lifecycle`, `ready`, `status`.
- While `DRAINING` / `STOPPED`: `ready: false`, `status: "not_ready"`, HTTP **503**.
- Developer Console Server Health shows lifecycle badge (`RUNNING` / `DRAINING` / `STOPPED`).

### Console during drain

- HTTP + `/console` gateway remain up until drain wait finishes, then ordered teardown closes console gateway, sockets, then HTTP.

### Configuration

- `GRACEFUL_SHUTDOWN_TIMEOUT_MS` (default `30000`) via `loadProductionConfig` / `.env.example`.

### Metrics

| Metric | Type | Meaning |
|--------|------|---------|
| `shutdownStarted` | counter | Drain began |
| `shutdownDuration` | timing | Drain+shutdown wall time (recorded at STOPPED) |
| `forcedShutdown` | counter | Drain timeout forced teardown |

(Requires `METRICS_ENABLED=true` or development mode for MetricsService recording.)

## Manual operator checklist

1. Start server with `GRACEFUL_SHUTDOWN_TIMEOUT_MS=30000`.
2. Open Developer Console → Server Health shows **RUNNING**.
3. Create a room (succeeds).
4. Send SIGTERM (or call programmatic shutdown).
5. Console shows **DRAINING**; `/health` returns **503** `not_ready`.
6. Attempt `createRoom` → rejected (`SERVER_DRAINING`).
7. Existing in-flight games continue until idle or timeout.
8. Process exits cleanly; logs show lifecycle transitions + shutdown duration.
9. No orphan intervals after exit (process gone).
