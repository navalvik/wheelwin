# R8.1A / R8.1B — Mainnet Dry Run Preparation & Wallet Verification

**Status:** Preparation and validation only.  
**Does not enable:** Mainnet gameplay, Mainnet GameEscrow production usage, or payment migration.

This stage answers: **Is WheelWin ready to perform a controlled Mainnet deployment?** with a deterministic **PASS** / **FAIL**.

R8.1B additionally proves:

```text
Railway mnemonic
    ↓
WalletContractV4R2
    ↓
TON_MAINNET_DEPLOYER_EXPECTED_ADDRESS
```

without creating a new wallet or changing derivation.

## Defaults (unchanged)

| Network | Escrow default | Notes |
|---------|----------------|-------|
| Testnet | `game` | GameEscrow remains the testnet path |
| Mainnet | `v4` | GameEscrow **not** production-enabled |

- Feature flag `GAME_ESCROW_MODE` retained
- Deployer wallet remains `WalletContractV4R2`
- No player payment / settlement / TonConnect / Page4–6 changes

## Mainnet wallet configuration steps (R8.1B)

1. Keep the **existing Railway** `TON_DEPLOYER_MNEMONIC` (do not generate a new mnemonic).
2. Derive identity with the existing path (`WalletContractV4R2`, workchain `0`) — use readiness script or startup diagnostics.
3. Set **both** Mainnet pins to that **same** bounceable address (explicit; no fallback):
   - `TON_MAINNET_DEPLOYER_EXPECTED_ADDRESS=<derived EQ...>`
   - `TON_MAINNET_ORACLE_ADDRESS=<same EQ...>`
4. Keep `TON_MAINNET_GAME_ESCROW_MODE=v4` (or unset → default `v4`).
5. Keep `TON_NETWORK=testnet` during dry-run (do not switch production yet).
6. Run `node server/scripts/check-mainnet-readiness.js` and confirm **PASS**.

## Validation steps

1. Load separated profiles from `server/config/tonNetworkProfiles.js` (`testnet`, `mainnet`).
2. Validate Mainnet configuration (required env, network, wallet config, artifact, escrow mode).
3. Validate oracle + expected addresses are valid TON addresses and **match each other**.
4. Probe deployer wallet identity (`WalletContractV4R2`, workchain, wallet id, derived address).
5. Compare derived address to `TON_MAINNET_DEPLOYER_EXPECTED_ADDRESS` (mismatch = FAIL; error includes derived, expected, network).
6. Verify `GameEscrow.code.boc` exists, SHA256 matches, and is loadable by the StateInit builder.
7. Confirm rollback safety: Mainnet escrow mode is still `v4`.
8. Review diagnostics / readiness script output.

## Wallet verification procedure

1. Ensure Railway (or local `.env`) has `TON_DEPLOYER_MNEMONIC` set to the **existing** production mnemonic.
2. Set `TON_MAINNET_DEPLOYER_EXPECTED_ADDRESS` and `TON_MAINNET_ORACLE_ADDRESS` to the known verified bounceable address for that mnemonic.
3. Run:

```bash
# PowerShell
$env:TON_MAINNET_WALLET_IDENTITY_DEBUG="true"
node server/scripts/check-mainnet-readiness.js
```

4. Confirm checks:
   - `wallet derivation: PASS`
   - `expected address match: PASS`
   - `oracle configuration: PASS`
5. Optional: inspect `TON_MAINNET_WALLET_IDENTITY_DEBUG` for network, wallet type, workchain, walletId, derived/expected/oracle addresses, balance, seqno, timestamp.

## How to run

From repo root:

```bash
node server/scripts/check-mainnet-readiness.js
```

With diagnostics:

Exit code: `0` = **PASS**, `1` = **FAIL**.

## Failure scenarios / examples

| Scenario | Result |
|----------|--------|
| Missing `TON_MAINNET_ORACLE_ADDRESS` | **FAIL** — `TON_MAINNET_ORACLE_ADDRESS is not configured` |
| Missing `TON_MAINNET_DEPLOYER_EXPECTED_ADDRESS` | **FAIL** — expected address not configured |
| Invalid address string | **FAIL** — `... is not a valid TON address` |
| Oracle ≠ expected deployer | **FAIL** — must match (shows both + `network=mainnet`) |
| Derived wallet ≠ expected | **FAIL** — `identity mismatch \| derived=... \| expected=... \| network=mainnet` |
| Invalid escrow mode (not `v4` / `game`) | **FAIL** (hard error, no silent fallback) |
| `TON_MAINNET_GAME_ESCROW_MODE=game` | **FAIL** (rollback safety — GameEscrow not enabled) |
| Artifact missing or SHA mismatch | **FAIL** |
| Mnemonic absent | wallet derivation / expected match **SKIP** (overall **FAIL** if config incomplete) |

On `TON_NETWORK=mainnet`, startup uses the same gates and **fails process start** on invalid Mainnet configuration (no silent fallback). Testnet active runtime is unchanged.

## Rollback behavior

R8.1A/B keep Mainnet on **v4**:

```text
Mainnet dry-run / issue
    ↓
TON_MAINNET_GAME_ESCROW_MODE=v4   (default)
GAME_ESCROW_MODE=v4               (active rollback switch when needed)
    ↓
restart backend
    ↓
new games use WalletContractV4 path
```

- No Mainnet GameEscrow production cutover in this stage
- Testnet continues with GameEscrow (`game`) by default
- Emergency rollback docs: [Mainnet-Architecture.md](../architecture/Mainnet-Architecture.md#emergency-rollback)
