## 5. Root cause classification

Based **only** on extracted archive evidence:

| Category | ROOM_bXwC | ROOM_HxV5 | Evidence |
|----------|-----------|-----------|----------|
| **Deploy timeout** | **Yes** | **Yes** | Explicit `deployer_seqno_confirmation_timeout`; `SEQNO_WAIT_TIMEOUT` stage; ~31 s window; 24–25 polls |
| RPC/provider failure | **No** | **No** | `broadcastResult: SUCCESS`; `tonCenterStatus/Response: null` (no HTTP error recorded) |
| Contract initialization failure | **No** | **No** | Never reached `initGame` / `openPayments`; failure during seqno confirmation after broadcast |
| Configuration failure | **No** | **No** | Oracle, owner, escrow address, code/data hashes present in `gameEscrowDeploy` |
| Deployer wallet failure | **Contributing** | **Contributing** | Same deployer; seqno stuck at `100` across both sessions 4 min apart; `matchedTxHash: null` |
| Unknown | **No** | **No** | Error string is explicit |

**Primary classification:** **Deploy timeout** (`deployer_seqno_confirmation_timeout`).

**Mechanism:** Deploy BOC was accepted for broadcast, but the server’s seqno confirmation loop never observed the deployer wallet seqno advance from `100` to `101` within the polling window.

Both sessions:

```text
deployer_seqno_confirmation_timeout
  operation=DEPLOY
  sentSeqno=100
  lastSeen=100
  deployer=EQB83s9XMOMseDFxyXxj4hrC0sS4FB4xhdNiUPkl_3zx3PDQ
  polls=24|25
```

This is the string passed through `GAME_CONTRACT_DEPLOY_FAILED` → `PaymentSessionManager.failSession()` → `PAYMENT_FAILED`.

**Not** payment timeout, **not** client TonConnect/STAKE failure, **not** TonCenter HTTP rejection at broadcast time.
