## Architecture

```text
Providers (lifecycle / logging / monitoring / HTTP / sockets)
  → HealthManager.refresh() (interval, unref'd)
      → StartupProbe | LivenessProbe | ReadinessProbe | OverallHealthProbe
  → Cached snapshot
  → HTTP probes + HealthService.getHealthSnapshot() + Console
```

`HealthService` delegates readiness / deployment fields to `HealthManager`.  
Probe HTTP handlers read **cache only** (lock-free).

---

## Probe semantics

| Probe | Pass when | Fail when |
|-------|-----------|-----------|
| Startup | Config + lifecycle + logging + monitoring + failure policy + HTTP + Socket.IO init | Incomplete init (latches permanently once true) |
| Liveness | Process operational | Unrecoverable internal failure only (drain stays live) |
| Readiness | `RUNNING` + deps ready | `DRAINING` / `STOPPED` / missing deps |
| Health | Overall ops summary | not_ready / unhealthy |

---

## HTTP endpoints

| Path | 200 | 503 |
|------|-----|-----|
| `/health` | ready + status ok | not ready (existing semantics preserved) |
| `/ready` | readiness pass | not ready / draining |
| `/live` | liveness pass | unrecoverable failure |
| `/startup` | startup latched | still initializing |

Cache-Control headers come from the deployment profile.
