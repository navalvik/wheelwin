## 3. Architecture Findings

The client creates a single shared Socket.IO instance at module load, before React renders, with `autoConnect: false` and infinite reconnection. The factory is the correct and only place to attach handshake auth — no second connection, no React-level creation, no custom reconnect logic.

## 4. Lifecycle Flow

1. Module import → `resolveTelegramInitData()` reads `globalThis.window?.Telegram?.WebApp?.initData` synchronously.
2. Telegram Mini App: non-empty string → sent verbatim as `auth.telegramInitData`.
3. Standard Web: Telegram absent / initData empty / non-string → empty string.
4. Socket.IO attaches the static `auth` object to every connect attempt, including all automatic reconnections — no custom reconnect handling required.
5. Server validates the signature via the existing validator (9bc9276) during handshake.

## 5. Ownership Boundaries

- Client: forwards raw initData only. No parsing, no validation, no storage, no logging.
- Server: sole owner of initData cryptographic validation and authentication decisions.
- Unauthenticated Web clients are accepted by the server as unauthenticated (JOIN_ROOM allowed, CREATE_ROOM denied later) — unchanged behavior.

## 8. Changes Made

### Exact client socket change (`client/src/socket/socket.js`)

Added exported helper and `auth` option:

```js
export function resolveTelegramInitData() {
    const rawData = globalThis.window?.Telegram?.WebApp?.initData;
    return typeof rawData === "string" ? rawData : "";
}

const socket = io(SOCKET_URL, {
    auth: {
        telegramInitData: resolveTelegramInitData()
    },
    autoConnect: false,
    reconnection: true,
    reconnectionAttempts: Infinity,
    reconnectionDelay: 1000,
    reconnectionDelayMax: 5000
});
```

All other options byte-for-byte unchanged. Singleton default export preserved.

### Tests (`client/src/socket/socket.telegramAuth.test.js`)

Covers all 7 required cases:

1. Telegram environment: mocked `window.Telegram.WebApp.initData`; asserts `socket.auth.telegramInitData === <exact raw string>`.
2. Standard Web: `window.Telegram` deleted → empty auth value.
3. Telegram present but initData empty (and undefined) → empty auth value.
4. `initDataUnsafe.user.id` set to a distinct value; asserts it is never used and not referenced in auth payload.
5. Scans all non-test client source files for `TELEGRAM_BOT_TOKEN`, `HMAC_SECRET`, and bot-token-shaped literals — none found.
6. Existing options unchanged: `autoConnect false`, `reconnection true`, `reconnectionAttempts Infinity`, delays 1000/5000 (verified via `socket.io.opts`).
7. Singleton: repeated dynamic import returns identical instance.

No Telegram cryptographic validation tested here (covered by `server/tests/telegramInitDataValidator.test.js`).
