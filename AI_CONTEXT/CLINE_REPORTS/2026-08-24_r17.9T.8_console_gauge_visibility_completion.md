# R17.9T.8 — Developer Console Gauge Visibility Completion

Date: 2026-08-24

Task: narrowly scoped completion of R17.9T.8 — make the already-collected R17.9T.8 room-pool gauges visible in the existing Developer Console Metrics panel. No behavior, security, gameplay, or financial changes.

## 1. Discovered Gap

Production `/debug` Metrics panel showed only Active players / Games / Timing samples / Counters ("No counters yet."). The R17.9T.8 gauges were being collected in production (verified via `/health`: gameplay collector healthy) but never reached the console UI.

## 2. Root Cause (source inspection of 7a21121)

- Gauges live in `MonitoringManager`'s `MetricsRegistry`, exposed only through `MonitoringManager.getSnapshot()` → `MetricsSnapshot.gauges` / `.counters` (`{name: number}` maps).
- `buildMetricsOverview()` consumed only `metricsService.getSnapshot()` (counters/timings) and the health blob — it **never read the monitoring snapshot**, so all registry gauges (including `gameplay.room_pool_*` and velocity/total gauges) were dropped from the console projection.
- `MetricsPanel.jsx` had no gauge section at all.

## 3. Design Decision (minimal)

- Backend: pass the read-only `monitoringManager` into the existing projection; project a frozen `gauges` map plus an explicit null-safe `roomPool` object (max / utilization / nearCapacity / createdPerMin / limitRejectionsPerMin / createdTotal / limitTotal). Existing DI convention preserved.
- Frontend: new pure helper `metricsRoomPool.js` (formatting + row mapping, null-safe); MetricsPanel gains one "Room pool (R17.9T.8)" DataTable section reusing existing `DataTable`/section-title conventions. No page redesign.
- Formatting: utilization → percent; per-minute → 1 decimal; near-capacity → "YES"/"no"; unavailable → "—".
