## R17.8V.2C Player Wallet Initialization Fix

**Date:** 2026-08-15  
**Network:** testnet  
**Scope:** harness only — Scenario B + C @ **0.05** (Scenario A already PASS in V.2B)  
**Launcher:** `node server/scripts/run-v2c-bc-live.js`  
**Artifact:** `server/tests/testnet/artifacts/valueton-sweep-last-run.json`  
**Production lifecycle / GameEscrow / Payment / Recovery:** **unchanged**

### Root cause

1. **Primary (V.2B):** ephemeral player wallets were **funded but not deployed**. Wallet V4 `getSeqno` on uninitialized accounts → exit **-13**; STAKE never reached.
2. **Secondary (first V.2C attempt):** after StateInit deploy, STAKE used default wallet `sendMode = NONE (0)`, so forward fees were taken from the attach. GameEscrow requires `context().value == required` exactly → STAKE **bounced**, `paidMask` stayed 0.

### Fix (Option A)

Harness-only changes in `server/tests/testnet/runValueTonSweep.js`:

- Deploy ephemeral Wallet V4 with **StateInit** before STAKE; wait until **active** and `seqno >= 1`.
- Refuse STAKE if wallet is not active.
- Use `SendMode.PAY_GAS_SEPARATELY | IGNORE_ERRORS` (mode 3) so exact stake amount arrives.
- Wait for player seqno advance after STAKE; poll `paidMask`.
- Test-only logs: address, active status, deployment status, balance before/after stake (no secrets).

## How to run

### Dry-run (no chain)

```bash
node server/scripts/run-testnet-valueton-sweep.js --dry-run
```

### Live testnet sweep

```bash
# server/.env must provide TON_DEPLOYER_MNEMONIC and testnet endpoint/key
set TON_NETWORK=testnet
set TON_DEPLOY_MODE=live
set RUN_TESTNET_VALUETON_SWEEP=true
set TEST_VALUETON_OVERRIDE=true
set TEST_VALUETON_SWEEP_VALUES=0.05,0.04,0.03,0.025,0.02,0.015,0.01
set TEST_VALUETON_SCENARIOS=A,B,C
set TEST_VALUETON_STAKE_TON=0.05
```
