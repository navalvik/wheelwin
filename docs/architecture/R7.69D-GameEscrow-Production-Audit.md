## Critical fixes applied in this commit

| ID | Issue | Fix |
|----|-------|-----|
| C1 | `INIT_GAME` oracle fell back to `players[0].wallet` when snapshot lacked `oracleWallet`, so on-chain oracle could become a player (OPEN_PAYMENTS / SETTLE / CANCEL would then reject deployer, or worse grant player oracle rights). | `GameContractManager` now uses `deployAdapter._tonConfig.oracleAddress` and fails with `oracle_address_missing` — never a player wallet. |
| C2 | `BlockchainMonitor` confirmed deposits from inbound transfer shape alone: aborted/bounced txs and non-STAKE transfers matching wallet+amount could emit `PAYMENT_BLOCKCHAIN_CONFIRMED` without GameEscrow `paidMask`. | Reject aborted/failed txs; when `playerIndex` is set, require on-chain `getPaidMask` bit before confirm. |

**Files changed:**  
`server/gameplay/GameContractManager.js`, `server/payment/BlockchainMonitor.js`, `server/tests/blockchainMonitor.test.js`, this report.

## Passed

### A — Legacy V4 (when `GAME_ESCROW_MODE=game`)

| V4 dependency | Classification | Notes |
|---------------|----------------|-------|
| `WalletContractV4` as **deployer/oracle signing wallet** (`TonGameContractAdapter._sendOracleMessage`, identity diagnostics) | **required** | Standard TON wallet; not escrow. |
| `buildV4EscrowWallet` / `serializeLegacySettleBody` / V4 settle confirmation via deployer tx | **temporary compatibility** | Active only when mode=`v4` (rollback). Not used as escrow when mode=`game`. |
| Mainnet profile default `gameEscrowMode=v4` + readiness warn/fail if mainnet≠v4 | **temporary compatibility** | R7.68 staged gate; explicit `TON_MAINNET_GAME_ESCROW_MODE=game` for cutover. |
| Tests constructing `WalletContractV4` for addresses | **required** (test fixtures) | Not production escrow. |
| Comment-based TonConnect payload fallback | **temporary compatibility** | Client prefers STAKE body when `playerIndex` set. |

**When mode=`game`:** escrow StateInit is GameEscrow (`buildGameEscrowStateInit`); settle body is GameEscrow SETTLE; settlement completion requires payout proofs (`GAME_ESCROW_SETTLEMENT_VERIFIED`), not deployer tx alone. No path found where V4 **escrow** address overrides GameEscrow contract address for deploy/pay/settle.

### B — Backend authority

- GameEscrow getters (`get_paid_mask`, `get_status`, settlement/cancel getters) are the payment/cancel truth via `BlockchainMonitor.readGameEscrowPaymentState` / `readGameEscrowCancelState` and `PaymentSessionManager.syncFromGameEscrow` (chain wins; demotes stale confirmed cache).
- Settlement in game mode: `SETTLEMENT_PENDING_CONFIRMATION` → monitor verifies winner+owner payouts + settled status → then `_confirmSettlement`. Missing payout watch → fail (`game_escrow_payout_watch_unavailable`), not optimistic complete.
- Refunds: `GAME_ESCROW_REFUND_CONFIRMED` only after chain observation (no optimistic).
- **Post-fix:** stake confirmation also requires non-failed tx + `paidMask` bit when seat index is present.

### C — State sync

- Recovery (`TonFinancialRecovery`) syncs from GameEscrow before re-registering payment watches; cancel sessions restore refund watches only (no refund resend).
- Settlement restore re-registers GameEscrow payout watches for `SETTLEMENT_PENDING_CONFIRMATION`.
- Duplicate payment/settlement/observation keys: tx hash sets, payment references, `_emittedObservations`, `DuplicatePaymentError` / `DuplicateSettlementError`.
- Blockchain wins over PaymentSession cache on sync (promote/demote).

### D — Watcher lifecycle

- `watchPayment` idempotent by `(roomId, playerId)` Map key.
- Unwatch on confirm / reject / expire / session complete / cancel (`stopRoom`).
- Settlement/refund watches: idempotent by watchId; only `PENDING` polled.
- Restart: payment watches from sessions + sync; settlement watches from persisted settlement sessions; refund watches from checkpoint + cancelled sessions.

### E — Resource lifecycle

- Payment watches cleared on FULLY_PAID / CANCELLED / destroy.
- Settlement success: `_cleanupAfterSuccess` nulls request + `destroySession` on payment session.
- Contract terminal statuses skipped on recovery re-register.

### F — Contract integrity (`GameEscrow.tact` + `contracts/tests/GameEscrow.spec.ts`)

- Storage: status, oracle/owner, hashes, paidMask/totalPaid/stakes, settled, refundMask/cancelReason.
- Transitions: UNINITIALIZED → DEPLOYED → WAITING_PAYMENTS → PAYMENTS_OPEN → READY → SETTLING → SETTLED; cancel to CANCELLED from PAYMENTS_OPEN/READY.
- Rejects: duplicate STAKE, wrong sender/amount, STAKE after READY/SETTLED, SETTLE before READY / duplicate settle, cancel after settle / double cancel, non-oracle settle/open/cancel.
- Empty `receive()` rejects player deposits once payments open (STAKE required).
- Getters authoritative for status, paidMask, player payment, settlement info, cancel status.

### G — Diagnostics

Sufficient for deploy / INIT / OPEN / settle / payout confirm / refund / wallet identity / mainnet readiness / artifact SHA (`DeployPipelineForensics`, GameEscrow deploy/settle/confirm debug, `TonMainnetReadiness`, `TonWalletIdentityDebug`). No mandatory gaps for Mainnet cutover.

### H — Configuration

- Explicit mode resolution; empty/unknown `GAME_ESCROW_MODE` throws.
- Testnet default `game`; Mainnet profile default `v4` with dedicated `TON_MAINNET_*` keys.
- Artifact present + SHA enforced when network=mainnet or mode=game; mismatch fails startup.
- Mainnet active network requires readiness `PASS` + `assertMainnetStartupSafe`.

### I — Security (implementation review)

- On-chain: oracle-gated OPEN/SETTLE/CANCEL; player-gated STAKE; amount/seat checks; settled/cancel duplicate guards.
- Off-chain: deployer mnemonic signs oracle messages; replay via seen tx / observation keys / session tx maps.
- **Post-fix:** INIT oracle no longer player-fallback; payment confirm gated by paidMask + aborted rejection.

## Phase notes (A–I)

### A — Legacy V4 audit summary

Under `GAME_ESCROW_MODE=game`, V4 does **not** act as escrow, does **not** run V4 settlement body, does **not** confirm settlement from deployer tx alone, and does **not** override GameEscrow address. Remaining V4 usage is deployer wallet (**required**) plus rollback path (**temporary compatibility**). Do not remove compatibility yet.

### B — Exceptions (payment/settlement confirmation)

1. **Fixed:** transfer-shape payment confirm without chain success/`paidMask`.  
2. **V4-only (compat):** settlement may complete from settlement tx watch without payout proofs.  
3. **API surface:** `PaymentSessionManager.confirmBlockchainPayment` can be invoked directly (tests/tools); production wiring is monitor events only.

### Cutover plan (ops, not code)

1. Keep Railway on testnet until go-live window.  
2. Fill Mainnet profile + artifact SHA; `check-mainnet-readiness.js` (update readiness gate when enabling `game` — W7).  
3. Set `TON_MAINNET_GAME_ESCROW_MODE=game` / active `GAME_ESCROW_MODE=game` in dedicated release.  
4. Verify deploy → INIT_GAME → OPEN_PAYMENTS → STAKE → SETTLE → payout proofs → refund path on Mainnet.  
5. Rollback: `GAME_ESCROW_MODE=v4` + restart (new games); in-flight GameEscrow finish on deployed contracts.
